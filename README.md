# Marketplace Product Classifier

Классификация карточек товаров русскоязычного маркетплейса по категории верхнего уровня (`greatgrandparent_category`, 39 классов).
Проект сравнивает три подхода на одном и том же стратифицированном split: TF-IDF + LinearSVC, дообученный RuBERT-tiny2 и Qwen2.5-0.5B с LoRA.
Основной акцент: честная методология (одинаковый split, чистые абляции, проверка утечек, доверительные интервалы) и разбор ошибок.

**Seed во всём проекте: `777`.** Модель: [ссылка на Hugging Face Hub](https://huggingface.co/theal1ve/marketplace-rubert-tiny2-category).

## Главные выводы

1. **На полных данных различия между подходами малы.** TF-IDF + LinearSVC (около 8 минут на CPU) даёт на test Accuracy 0,971 и Macro F1 0,949. RuBERT-tiny2 (V2) добавляет +0,24 п.п. по accuracy, а по Macro F1 различия нет (0,9493 против 0,9491). На validation прирост V2 по accuracy +0,27 п.п. (95% ДИ [+0,16; +0,39]); преимущество по Macro F1 там (+0,34 п.п.) статистически не подтвердилось (ДИ [−0,13; +0,81]).
2. **Weighted CE реально помогает RuBERT-tiny2.** В чистой абляции (одинаковые гиперпараметры, 3 seed'а) Macro F1 выше на +1,5 п.п. при всех seed'ах, accuracy не ухудшается.
3. **Утечка есть, но слабая.** 7,18% test-карточек дословно встречаются в train; без них метрики V2 снижаются не более чем на 0,35 п.п.
4. **При ограниченных данных (100k карточек, 1 эпоха) лучше всех Qwen2.5-0.5B + LoRA**, но ценой в десятки раз более дорогого обучения и инференса; TF-IDF обгоняет RuBERT-tiny2 в этом режиме.
5. **Остаточные ошибки сосредоточены в смежных по смыслу категориях**, и в просмотренных вручную примерах разметка во всех случаях спорная.

## Данные

[nyuuzyou/ke-products](https://huggingface.co/datasets/nyuuzyou/ke-products): 2 059 468 карточек, после удаления строк без целевой категории 1 401 862 и 39 классов.
Классы несбалансированы (от 205 до 190 676 карточек). Вход модели: `title + description` без HTML.
Split 90/5/5, стратифицированный по классу: train 1 261 675, validation 70 093, test 70 094. Split сохранён в файл (`artifacts/split_ids.parquet`) и воспроизводится одинаково локально и на Kaggle (проверка по id).

## Основные эксперименты (validation)

| Модель | Вход | Loss | Accuracy | Macro F1 | Weighted F1 |
|---|---|---|---:|---:|---:|
| TF-IDF + LinearSVC | title + description | squared hinge | 0.9697 | 0.9496 | 0.9696 |
| V1: RuBERT-tiny2 | title + description | Cross-Entropy | 0.9682 | 0.9388 | 0.9685 |
| **V2: RuBERT-tiny2** | title + description | Weighted CE | **0.9724** | **0.9530** | 0.9724 |
| V3: RuBERT-tiny2 | title + description + attributes | Weighted CE | 0.9726 | 0.9522 | 0.9726 |

V2 выбрана по validation Macro F1. Обратите внимание: V1 и V2 обучались с разными batch size (64 против 16), warmup и fp16, поэтому
прирост V1 → V2 нельзя целиком приписать weighted loss; это проверено отдельной абляцией (ниже).

**Финальный test (V2, один раз после выбора модели):** Accuracy 0.9734, Macro F1 0.9493, Weighted F1 0.9734.
Test для обоих подходов (считался один раз после заморозки конфигурации):

| Модель | Accuracy | Macro F1 | Weighted F1 |
|---|---:|---:|---:|
| TF-IDF + LinearSVC | 0.9710 | 0.9491 | 0.9709 |
| V2: RuBERT-tiny2 | **0.9734** | 0.9493 | **0.9734** |

На test выигрыш V2 по accuracy сохраняется (+0,24 п.п.), а по Macro F1 различия нет (+0,02 п.п.). На validation V2 выигрывала и по Macro F1, но V2 выбиралась по validation среди эпох,
поэтому там её оценка оптимистична: при переходе с validation на test Macro F1 V2 падает на 0,37 п.п., у TF-IDF (без подбора) на 0,05 п.п.

## Чистая абляция loss

Условия: подвыборка train 200 000, 2 эпохи, lr 3e-4 (выбран по короткому подбору), batch 32, warmup 10% шагов, один и тот же код для обеих веток
(меняются только веса классов), 3 seed'а, оценка на полном validation, Kaggle T4.

| Ветка | Macro F1 (среднее ± std) | Accuracy (среднее) |
|---|---:|---:|
| Cross-Entropy | 0.9016 ± 0.0019 | 0.9551 |
| Weighted CE | 0.9166 ± 0.0041 | 0.9558 |

Разность Macro F1: +0.0150 (std 0.0056, n = 3); по seed'ам +0.0112, +0.0124, +0.0214. Weighted CE выше при каждом seed'е, accuracy при этом не падает.
Ограничения: три seed'а, подвыборка и короткое обучение; в полном режиме (1,26M карточек, 5 эпох) эффект мог бы отличаться.

## Сравнение V2 и TF-IDF (validation, парный bootstrap, 2000 повторов)

| | Разность V2 − TF-IDF | 95% ДИ |
|---|---:|---|
| Accuracy | +0.0027 | [+0.0016; +0.0039] |
| Macro F1 | +0.0034 | [−0.0013; +0.0081] |

Тест Мак-Немара: p < 1e-6 (V2 верна и TF-IDF ошибается в 851 случае, наоборот в 660). V2 лучше на семантически близких классах («Детская одежда»,
«Уход за волосами»), TF-IDF на классах с характерной лексикой. Ограничения: V2 выбиралась по validation среди эпох, у TF-IDF гиперпараметры не подбирались. Парный bootstrap на test: [результат `06_compare_models.py --part test`].

## Проверка пересечений train/test (V2 на test)

| Подмножество test | n | Accuracy | Macro F1 |
|---|---:|---:|---:|
| Весь test | 70 094 | 0.9734 | 0.9494 |
| Без дублей по тексту (7,18%) | 65 064 | 0.9721 | 0.9476 |
| Без дублей по title (22,87%) | 54 065 | 0.9706 | 0.9459 |

У дублей по тексту метка совпадает с меткой в train в 99,38% случаев. Дубли по title не обязательно утечка (одинаковые названия у разных товаров), это нижняя граница.

## Сравнение подходов при одинаковом бюджете (100 000 карточек, 1 эпоха)

Одна и та же подвыборка train, оценка на полном validation, один seed.

| Модель | Accuracy | Macro F1 | Обучение | Примечание |
|---|---:|---:|---|---|
| TF-IDF + LinearSVC | 0.9449 | 0.8848 | 174 с (CPU, с подготовкой данных) | |
| RuBERT-tiny2, weighted CE | 0.9386 | 0.8488 | 297 с (T4, с оценкой) | lr 3e-4 |
| Qwen2.5-0.5B + LoRA, weighted CE | **0.9489** | **0.9050** | 5786 с (T4) | lr 2e-4 |

Qwen: обучаемых параметров 8,83 млн из 502,9 млн (1,76%), пик памяти GPU 10,5 ГБ, инференс 57 карточек/с на T4. Токенов на карточку в среднем 155.70756, усечено до 256 токенов 0.27004.
Разность Qwen − TF-IDF (парный bootstrap): accuracy [X; ДИ], Macro F1 [X; ДИ].

Как читать: при малом бюджете предобученная LLM эффективнее по данным, чем крошечная модель, а TF-IDF сильнее RuBERT-tiny2 (которому не хватило шагов: 3125 при lr 3e-4,
подобранном на коротком прогоне). На полных данных (5 эпох, 1,26M карточек) RuBERT-tiny2 догоняет и слегка обгоняет TF-IDF по accuracy. Цена LLM: обучение примерно в 20 раз
дольше, инференс примерно в 17 раз медленнее, чем у RuBERT-tiny2. Ограничения: один seed, lr не подбирался заново на этом бюджете, одна эпоха, Qwen усекает больше текста.

## Разбор ошибок и шум таксономии

- В train 346 различных текстов (из 1 200 543) встречаются с противоречивыми метками (1351 строка, 0,11%), 141 из них это пара «Детская одежда» ↔ «Одежда».
  Это нижняя оценка шума: учитываются только дословные дубли.
- V2 на validation делает 1934 ошибки (2,76%); топ-10 пар путаниц покрывают 36,0% ошибок.

| Пара путаниц | Ошибок (в обе стороны) | Доля всех ошибок |
|---|---:|---:|
| Детская одежда ↔ Одежда | 225 | 11,6% |
| Товары для дома ↔ Хобби и творчество | 152 | 7,9% |
| Товары для дома ↔ Товары для кухни | 151 | 7,8% |
| Аксессуары ↔ Хобби и творчество | 94 | 4,9% |

- Ручной разбор: из 75 примеров (по 15 для пяти крупнейших путаниц, около 24% всех ошибок) разметка во всех случаях оценена как спорная. Разметчик один (автор проекта),
  остальные 76% ошибок вручную не проверялись. [Примеры: `results/error_examples.csv`.]
- Следствие: часть «ошибок» модели вызвана пересекающейся таксономией (например, «Смартфоны и телефоны» и «Электроника»), и потолок качества задаёт разметка.

## Скорость и размер (V2)

29,2 млн параметров, 119 МБ. Замер на [модель CPU, 6 потоков] и RTX 3070, 200 запросов (batch = 1, вместе с токенизацией) и пропускная способность при batch 64:

| Вариант | p50, мс | p95, мс | карточек/с |
|---|---:|---:|---:|
| CPU fp32 | 4.5 | 9.7 | 283 |
| GPU fp16 (RTX 3070) | 4.6 | 5.4 | 2115 |
| CPU int8 (динамическое) | 7.3 | 11.9 | 404 |

int8-квантование Linear-слоёв выигрыша почти не дало (109,7 МБ, совпадение предсказаний с fp32 на 99,6% карточек).

## Ограничения

- Один маркетплейс и один язык; на других площадках качество не проверялось.
- Шумная, частично пересекающаяся таксономия: потолок качества определяется разметкой.
- Редкие классы (10–50 карточек в validation) оцениваются очень шумно, Macro F1 нестабилен.
- Абляция и сравнение с Qwen: мало seed'ов (3 и 1), подвыборки и короткие запуски.
- Сравнение при одинаковом бюджете не подбирает гиперпараметры отдельно для каждой модели.
